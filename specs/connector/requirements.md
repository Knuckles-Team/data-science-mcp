# CONN-DATA-SCIENCE-MCP — Requirements

Governing spec: [spec.md](spec.md).

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-DATA-SCIENCE-MCP-R001` | **Signed engine compute connection.** The connector must connect to the engine through the SDK compute adapter in `data_science_mcp/ml_engine.py`. The connection must sign the data-science and finance compute scopes and cache one probe result. Caller chain: The `data-science-mcp` console script runs `scion_sdk.cli:serve`, which loads `data_science_mcp/__init__.py::connector` (api=`MLEngine`); tools such as `fit_model` in `data_science_mcp/mcp_server.py` call `data_science_mcp/ml_engine.py::MLEngine._rust_client` (line 97), which calls `scion_sdk.compute.engine.connect_compute(scopes=ENGINE_SCOPES)`. Shape: `MLEngine._rust_client` signs `ENGINE_SCOPES` (compute:datascience, compute:finance, sparql:read) through the SDK `connect_compute` adapter and caches the client or the failed probe in `_rust_client_cache` against the `_UNPROBED` sentinel; failures are logged by type only. | `tests/test_engine_connection.py` must show: the adapter receives the compute scopes, the client is returned, and an unconfigured engine is probed once and logged by error type only. Test: `tests/test_engine_connection.py::test_connects_with_a_signed_compute_context`. |
| `CONN-DATA-SCIENCE-MCP-R002` | **Engine audience from the deployment.** The connector must sign engine requests with the audience in `MEDULLA_AUDIENCE`. The deployment must set it to the audience the engine expects. Caller chain: The `data-science-mcp` console script runs `scion_sdk.cli:serve`; `data_science_mcp/ml_engine.py::MLEngine._rust_client` calls `scion_sdk.compute.engine.connect_compute`, which builds `scion_sdk.ingest.engine.EngineSettings.from_settings` and signs the context through `verified_context()`. Shape: The audience is read from `MEDULLA_AUDIENCE` by `EngineSettings.from_settings` in scion-sdk; the connector adds no code and relies on the deployment setting the variable. | `tests/test_engine_audience.py` must show: the signed context carries the configured audience. Test: `tests/test_engine_audience.py::test_signed_context_carries_the_configured_audience`. |
| `CONN-DATA-SCIENCE-MCP-R003` | **Served tool uploads teacher scores.** Subsystem: served tool. Tool `upload_teacher_scores(scorer_id, scorer_revision, documents)` in `data_science_mcp`. For each document it runs the named scorer from `data_science_mcp/trainers/eval_hooks.py` (`Scorer`, default `grounded_scorer`) `DISTILL_SAMPLES` times, default 3, range [1, 9]. The score is the median in 16-bit fixed point. The fidelity bounds are the minimum and maximum. A deterministic scorer gives equal bounds. It uploads through `DistilledScoreUploader` of `SCION-CONNECTOR-CONTROL-R905`. It needs the actor-required flag of `SCION-CONNECTOR-CONTROL-R902.1`. Refusal: `SCORER_UNKNOWN`. Depends on: SCION-CONNECTOR-CONTROL-R905. Caller chain: (planned) The `data-science-mcp` console script runs `scion_sdk.cli:serve` and loads `data_science_mcp/__init__.py::connector`; the new `upload_teacher_scores` tool will be added through its `tool_registry`, and `data_science_mcp/trainers/eval_hooks.py::grounded_scorer` (line 31) exists today but nothing calls an uploader. Shape: Add a registration function beside `register_trainer_tools` in `data_science_mcp/mcp/mcp_trainers.py` and a `tool_registry` row in `data_science_mcp/__init__.py`; reuse `Scorer` and `grounded_scorer` from `data_science_mcp/trainers/eval_hooks.py` and the SDK `DistilledScoreUploader`; median and min/max over `DISTILL_SAMPLES`. | Test (planned): `tests/test_distilled_scores.py::test_tool_uploads_median_scores_with_bounds` (L3) calls the served tool with a recording uploader. |
